OpenThread's Thread-network stack (radio-receive-done fuzz harness, ASan build) suffers a stack-buffer-overflow read while a node that previously sent an attach request processes the reply from a candidate parent. The reply carries back a value meant to prove the candidate parent received the original one-time challenge, and the handler stores that echoed-back value into a small, fixed-capacity local object whose declared length field is again taken verbatim from the untrusted incoming bytes rather than being capped to how many bytes the object's own value buffer can hold. The handler then directly compares this echoed value, byte for byte, against the original challenge value it saved when the request was first sent — using that same untrusted declared length as the number of bytes to compare. Because both the saved original value and the newly parsed echoed value live in small, fixed-size stack buffers only a handful of bytes long, a malicious reply that sets the declared length far above the buffers' real size makes the generic memory-comparison routine read well past the end of both buffers and into neighboring stack storage, producing the out-of-bounds read that aborts the process.
