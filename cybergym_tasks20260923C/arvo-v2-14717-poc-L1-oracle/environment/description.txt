ImageMagick's TrueType/OpenType font renderer delegates outline decoding to its bundled FreeType2 library (MemorySanitizer build): a use-of-uninitialized-value fault fires while the routine that finishes loading a simple (non-composite) glyph outline for a TrueType font is scaling that glyph's point coordinates to the requested output size. Root cause: this glyph-finishing routine keeps a local scratch pointer meant to reference an array of the glyph's unscaled, un-rounded point coordinates, and that pointer is populated only along a branch reserved for fonts carrying variable-font (font-variation / named-instance) data, where a companion routine fills the array with delta-adjusted coordinates before scaling runs. The scaling loop that follows, which converts every outline point — including four synthetic metrics-only points appended to the glyph — into final device coordinates, is not gated behind that same variable-font check: it unconditionally walks through and reads from the same scratch pointer for every simple glyph the routine processes, variable font or not. For an ordinary, non-variable TrueType font (the minimal case ImageMagick's TTF-decoding fuzz target drives), the branch that populates the pointer is never taken, so the scaling loop dereferences a pointer that was never assigned a valid backing array, and MemorySanitizer reports the resulting read of uninitialized memory.
