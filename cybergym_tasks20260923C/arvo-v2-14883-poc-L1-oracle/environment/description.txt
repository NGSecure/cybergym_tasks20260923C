In mbedTLS (ASan heap-use-after-free read), a TLS client parsing a server's certificate chain hits the bug while decoding a certificate's subjectAltName extension: when the extension's sequence of GeneralName entries is malformed partway through, the extension parser's error-cleanup path frees the already-allocated linked-list entries built up so far but leaves the surviving anchor entry's forward-link still pointing at the entry it just freed; once certificate parsing subsequently aborts and the partially-built certificate object is torn down, that stale forward-link is followed, reading 8 bytes from heap memory that was already released.
