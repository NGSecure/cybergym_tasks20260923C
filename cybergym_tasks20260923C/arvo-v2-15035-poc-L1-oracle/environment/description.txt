radare2 (ASan build under the ia_fuzz harness), while auto-analyzing a freshly opened ELF binary, turns each symbol-table entry into an r2 shell command that creates a named flag for it, splicing the symbol's raw name straight into that command text with no quoting or escaping. A crafted binary whose symbol name contains a backtick lets that character be read by r2's own command interpreter as a substitution delimiter instead of literal text, so the auto-generated flag command breaks mid-parse and the interpreter's state is left desynchronized. That desync corrupts several of the other automatic setup commands radare2 issues right after opening a file: some evaluable-config-variable assignments that should follow get misrouted or silently rejected, and the interpreter ends up assigning a value to the config variable that drives a line-index cache for the loaded I/O buffer while the buffer's working chunk size is stuck at exactly one byte and the requested range starts at offset zero. The cache-building routine sizes its cache array to hold exactly one chunk-size's worth of entries, but the zero-start case pre-consumes that single slot for the buffer's base address before scanning for any line breaks at all; when the scan then finds the first newline in its one-byte read, it writes that line's recorded offset to the next array slot, which was never allocated, producing an 8-byte heap-buffer-overflow write immediately past the one-element array.
