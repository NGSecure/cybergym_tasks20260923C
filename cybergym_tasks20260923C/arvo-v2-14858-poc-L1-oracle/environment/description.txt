ImageMagick's TIFF reader (MemorySanitizer build, exercised through the Magick++ encoder fuzz harness) reports a use-of-uninitialized-value defect while importing pixel samples from a tiled image whose header declares the SGI LogLuv photometric interpretation together with a single sample per pixel. Earlier in the read-strategy selector, an interpretation this unusual is already steered toward the safe, scanline-by-scanline generic reader, since only a small handful of well-understood photometric interpretations are allowed to keep a faster method. But a later check -- one that looks only at whether the image is stored in tiles and how many samples each pixel carries, without re-examining which photometric interpretation is in play -- unconditionally switches any single-sample tiled image back onto the faster per-tile reader, silently discarding that earlier safe choice. Because this override never reconsiders the photometric interpretation, a LogLuv image with one sample per pixel ends up decoded by the per-tile reader despite having already been flagged for the generic path. That reader heap-allocates one working pixel buffer per tile and copies each decoded tile row into it before handing the buffer to the generic pixel-import routine, but for this photometric/compression combination the tile's actual decoded data does not fill that buffer out to the width the importer assumes, leaving some of the trailing 16-bit sample slots as raw, never-written allocator memory. When the grayscale-sample importer subsequently treats one of those 16-bit slots as a compact (half-precision-style) floating-point luminance value and expands it to full single precision for the in-memory pixel, it reads and arithmetically operates on the still-uninitialized bytes, which MemorySanitizer flags as a use of uninitialized value.
