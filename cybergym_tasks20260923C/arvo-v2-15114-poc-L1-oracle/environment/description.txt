OpenSSL's TLS client handshake fuzz target (AFL+ASan build): while finishing an SSLv3 handshake, the code path that computes a Finished-message digest needs to feed the session's master secret into the active digest implementation through the library's generic provider-parameter interface. A small helper builds the list of parameter descriptors for this hand-off, but one descriptor is built to point at a plain local integer (an operation-selector value) that only exists in the helper's own stack frame; the helper then returns, handing the parameter list back to its caller. The caller does not immediately consume the list — it is threaded down through several more calls and only actually dereferenced once it reaches the low-level parameter-reading accessor inside the digest's parameter-setting callback. By that point the helper's stack frame has already been reclaimed and possibly overwritten by later calls, so the accessor reads whatever garbage now occupies that stack slot instead of the operation-selector value the helper meant to pass. Root cause: a pointer into a function's own local stack storage is written into an out-parameter structure and dereferenced only after that function has returned, i.e. a stack-use-after-return via a parameter descriptor whose lifetime assumption (backing storage must outlive the whole parameter list's use) was violated by pointing at a callee-local variable instead of caller- or session-owned storage.
