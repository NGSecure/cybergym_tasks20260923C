A bug in open62541's default access-control plugin makes MemorySanitizer report a use-of-uninitialized-value read while tearing down the server config: an earlier failure inside the config's setup routine already triggered a premature cleanup of the access-control state (freeing its internal context) without clearing the config's access-control callback/context afterward, so when the server is later deleted the same cleanup runs a second time and the callback dereferences the already-freed context to read its login-count field.
