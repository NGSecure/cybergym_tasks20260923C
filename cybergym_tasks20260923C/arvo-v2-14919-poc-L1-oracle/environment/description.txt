HarfBuzz's font-subsetting fuzz target crashes with a 2-byte heap-buffer-overflow read while the subsetter walks a font's OpenType "style attributes" table to decide which name-table entries a variable-font's per-axis-value records still reference. Root cause: that table stores its axis-value records as an array of relative offsets that must be resolved against the start of the sub-array that actually holds them, but the code resolving each offset into a pointer instead added the address of the outer table's own start. Whenever that inner sub-array sits at a non-zero offset inside the outer table (the normal case, and easy to force with a small fuzzer-crafted font whose declared offset lands the record just past the tiny malloc'd input buffer), every pointer computed this way is short by exactly that sub-array's own offset, so the 2-byte "format" field of what the code thinks is the next axis-value record is actually read from a heap address a few bytes beyond the end of the allocated font-data buffer, tripping ASan.
