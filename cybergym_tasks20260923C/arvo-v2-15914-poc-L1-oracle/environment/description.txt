libxslt (MSan build): transforming a crafted XML document with a crafted XSLT stylesheet, where the transformation recurses through several nested levels of template invocation before producing its result, and then serializing that result directly (its outermost content is itself a text node, not an element wrapping further children) triggers a use-of-uninitialized-value warning while that outermost text content is escaped for output. Root cause: the same text-copying fast path described for sibling cases in this project applies here too — the engine keeps a single cached pointer to whichever output text buffer it most recently allocated, along with a count of how many of that buffer's bytes are genuinely populated, so an adjacent run of copied text can simply extend the existing buffer instead of allocating a new node. One of the branches that instead allocates its own independent text buffer (taken when the source text is shared from an interned string table) leaves that cached pointer and byte-count untouched on return. Several template-application levels later, a fresh allocation for a different, unrelated piece of text can coincidentally land at the same address the stale pointer still references, so the merge logic trusts a byte count left over from the earlier allocation; extending the buffer on that false premise leaves part of the new allocation uninitialized, and that portion is read back when the final result is serialized.
