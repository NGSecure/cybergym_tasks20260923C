This is a stack out-of-bounds read triggered while ImageMagick previews ("pings", without fully decoding) a crafted image wrapped in an EPS/EPT-style preview container, whose payload is handed off to the PostScript document-header scanner shared by ImageMagick's PostScript readers. That scanner stages the incoming bytes in a fixed-capacity buffer carried on the stack, refilling it by reading raw bytes straight from the input stream up to the buffer's full declared capacity every time it runs dry. Several of the scanner's helper routines then treat the staged bytes as an ordinary null-terminated string rather than a bounded byte range: for example, when the scanner wants to check whether the current document comment line names a particular process color, it hands a pointer into the buffer to a wildcard-matching routine, which in turn walks the string one prospective character at a time through a small multi-byte-sequence decoder that decides how many bytes the next character occupies before consuming them and moving on. Because the refill logic reads a completely full buffer's worth of bytes on each pass, it never reserves a spare byte at the tail to guarantee termination. When an attacker crafts the input so that a recognized comment (one whose keyword the scanner matches and then hands off for further parsing) extends all the way to the very last byte the buffer can hold, there is no zero byte anywhere in the staged data for the character-by-character scan to stop at. The multi-byte decoder then keeps advancing past the end of the buffer, one byte at a time, into whatever other stack-allocated variables of the enclosing frame happen to sit immediately afterward, producing a one-byte out-of-bounds read that only stops once it happens to hit a zero elsewhere on the stack (or is caught by a memory sanitizer first).
