libspng, a PNG-decoding library, crashes with an AddressSanitizer heap-use-after-free while its ancillary-chunk parsing loop processes the metadata chunks that precede a PNG file's image-data chunk. Root cause: for each chunk, the loop first caches a local pointer to the chunk-payload buffer, and only afterward calls the internal step that actually fills that buffer with the chunk's bytes read from the input stream -- a step that can resize the underlying heap allocation, freeing the old block and handing back a different one. Because the cached pointer was taken before this refetch rather than after it, one of the chunk-type-specific handlers reached later in the same dispatch chain bulk-copies almost the entire chunk payload out of what it believes is the freshly-read buffer, using the chunk's own recorded length as the copy size. Since that stale pointer refers to an already-freed block of exactly that size, the copy runs the full length of the freed allocation and slightly beyond its end, producing a wide, multi-kilobyte use-after-free read.
