This crash happens while the image library's tile-based reader hands a tile of pixel data off to an embedded, legacy variant of compressed-image decoding that the format still special-cases for old-style compressed strips. Before decoding, the reader pre-sizes a set of heap buffers meant to hold the luma and two chroma planes for the tile, based purely on the tile's declared width, height, and subsampling geometry taken from the file's own header tags; the buffers are allocated but not zero-filled, so every byte in them starts out as whatever the allocator's freshly-returned memory happened to contain. The actual decode step then calls into the underlying JPEG decompression library to populate those buffers, and the amount of data that library reports having produced is derived independently, from the compressed codestream's own internal component and minimum-coded-unit bookkeeping. When the input is malformed in a way that shrinks or degenerates this per-unit accounting relative to what the tile geometry predicted beforehand (for example a corrupted subsampling factor or component count that makes the codestream describe fewer, or more oddly shaped, coded units than the outer tile dimensions imply), the underlying decoder legitimately produces less output than the geometry-derived buffer size calls for, but the surrounding logic never compares the two byte counts and never treats that shortfall as an error condition; it simply proceeds as though the whole plane had been populated. The subsequent colorspace-conversion step that blends the sample planes into final pixel output then reads straight across the full buffer it was told to expect, including the trailing portion decoding never actually touched, so the arithmetic that combines the three planes consumes never-initialized heap bytes as if they were genuine sample data, which is what memory-safety instrumentation flags as a use of an uninitialized value.
