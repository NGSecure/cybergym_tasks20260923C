This is a heap-use-after-free read triggered while an image-drawing routine renders a curved segment of a path description embedded in the input image, expanding it into a series of interpolated points that get appended to a shared, dynamically growing coordinate buffer used for the whole drawing operation. Before producing those points, the routine derives a working pointer into that buffer at its current base address and offset, then invokes a capacity-check helper that may decide the buffer is too small for the additional points about to be written and grow it by reallocating; a reallocation is free to move the block to a new address, which invalidates any pointer that was computed against the old address. Because the working pointer had already been derived before this capacity check ran, once the check actually triggers a reallocation the routine keeps using that now-stale pointer to read back a value it expects to find at the previous location, but that location sits inside the block that has just been released and replaced. The read lands well inside what was originally a large, several-hundred-kilobyte allocation, at an offset that is only reachable once earlier points in the same curve have already been emitted, which is why the corruption only surfaces partway through processing a sufficiently long/complex curve rather than immediately. The underlying fix does not change the growth policy or the interpolation math at all; it simply re-derives the working pointer from the buffer's live base address again immediately after each point where the capacity check might have caused a reallocation, so every subsequent access is guaranteed to target the buffer's current location instead of a location that may already have been freed by a reallocation earlier in the same call.
