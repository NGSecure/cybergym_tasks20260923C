open62541's OPC UA binary-message fuzz harness (ASan build) crashes with a heap-buffer-overflow write while the server is still bootstrapping its own built-in information model, before any attacker-supplied protocol message is even parsed. Building that base model internally triggers a browse operation, which keeps a small growable array of already-visited node identifiers to avoid re-visiting duplicates; that array's very first allocation can fail under a constrained memory budget, but the browse code does not check the outcome of that initial setup and carries on regardless, leaving the dedup structure believing it has zero usable capacity. When the browse then records its first node reference, it sees that its current capacity is not greater than its current (also zero) element count and decides it must grow — but doubling a capacity that is already zero still yields zero, so the "grow" step reallocates to a zero-byte request. On Linux this degenerate reallocation quietly succeeds (it does not return a null pointer), so the failure goes undetected a second time, and the code proceeds to believe the buffer has room. It then unconditionally copies a full node identifier into that phantom slot, overrunning the essentially empty backing allocation. Reaching the bug requires only that the harness's own allocator budget be starved right at server startup — a fuzzer input built almost entirely to squeeze that first internal allocation, with no real protocol content needed at all.
