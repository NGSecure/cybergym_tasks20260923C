ImageMagick's ICO/CUR decoder (MSan build, exercised through the header-only "ping" entry point) reconstructs a standalone PNG byte stream for a directory entry whose embedded image is itself PNG-encoded, the same way it does for other crafted icons of this kind: a fixed PNG-signature-and-partial-header stub plus the entry's real payload bytes are written into a freshly allocated buffer, and that buffer is then handed to the generic PNG blob reader using a declared length that is a fixed amount larger than what was actually written, leaving a trailing span of uninitialized heap memory the reader believes is valid data. Unlike a crash reached through an unrecognized trailing chunk, this crafted icon's embedded-PNG payload is shaped so that the very first mandatory chunk after the signature — read directly from the top-level chunk-parsing entry point rather than through the generic unrecognized-chunk handling path — has its own data-and-check-value read extend into that always-uninitialized trailing span, so the crash surfaces while validating that leading chunk's trailing check value rather than while handling any later ancillary chunk.
