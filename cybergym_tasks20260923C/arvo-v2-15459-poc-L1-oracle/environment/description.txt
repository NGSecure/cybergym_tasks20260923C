This is a stack-buffer-overflow write of a fixed 4-byte quantity, caught by AddressSanitizer while a c-ares fuzz target feeds a raw DNS response into the library's legacy IPv4 address-reply parser -- the routine that turns an entire DNS response buffer into a hostent plus a caller-owned array of per-address TTL entries, alongside a caller-supplied count of how many TTL slots that array actually has room for. The crash mechanism is a missing bound check in the loop that copies parsed address records into the caller's array: for every resource record in the response that resolves to an address for the queried name, the parser writes another TTL/address entry at an ever-incrementing index, but never compares that index against the capacity the caller told it about before writing. A DNS response that legitimately contains more matching address records than the caller's array has slots for therefore drives the write index straight past the end of that array, overwriting adjacent stack memory one entry at a time until the corrupted stack state is detected. It is the number of matching address records the crafted response contains, not the response's overall byte length, that determines how far past the caller's array the out-of-bounds writes reach.
