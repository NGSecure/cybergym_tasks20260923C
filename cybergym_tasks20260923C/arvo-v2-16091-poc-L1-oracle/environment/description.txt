libspng's PNG pixel-decoding fuzz target (ASan build): a heap-buffer-overflow read happens while assembling a decoded row into the caller-supplied output buffer. The decoder keeps a small per-pass scanline buffer sized to hold only the pixel data belonging to the interlace pass currently being processed, and for one output pixel format there is a fast-path shortcut that copies that scanline straight into the destination row with a single bulk copy instead of converting pixel-by-pixel. Root cause: the byte count passed to that bulk copy is derived from the final, fully-deinterlaced image row width rather than from the width of the scanline buffer actually allocated for the current (narrower, sub-sampled) interlace pass, so on an Adam7-interlaced image the copy reads past the end of the undersized source buffer whenever this pass's scanline is shorter than a full output row.
