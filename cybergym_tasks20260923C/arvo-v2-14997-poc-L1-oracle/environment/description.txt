KArchive's fuzz target opens a crafted .tar container whose per-entry payload is bzip2-compressed, and the crash happens while the bundled bzip2 decoding library is unpacking one compressed block from that payload. Early in each block, the format encodes how many Huffman coding tables ("groups") were used and then how many selector entries follow, both read straight off the bitstream as attacker-controlled integers; the decoder loops once per declared selector entry, writing each one into a fixed-size table sized only for the format's documented maximum selector count. The loop bound comes from the value just read off the wire, but nothing clamps that value against the table's actual capacity before the write loop starts, so a block that advertises more selector entries than the table can hold drives the loop index past the end of the array on this exact input, producing an out-of-bounds array write detected as an indexing violation.
