radare2's Xbox executable-format reader (ASan build under the ia_fuzz harness) aborts with a heap-buffer-overflow read while it opens a candidate .xbe file: after only checking a four-byte magic tag at the very start of the file, the reader points a large fixed-size on-disk header structure straight at the raw input bytes and immediately pulls one of that structure's interior fields -- the program's entry-point value, used to tell a retail build apart from a debug or Chihiro-console build -- directly through that pointer, without ever confirming the input is even as long as the header structure it is being read through. A crafted file that is only a few bytes long, just enough to pass the magic check but nowhere near the header's real size, makes that very first interior-field access land far outside the small heap allocation backing the input, tripping ASan's guard before any real parsing of the binary can happen. Every other accessor in the same format handler -- the ones that build the entry-point record, the section table, the imported-library table, and the kernel-import table -- shares that same unchecked pointer, so the underlying flaw is a single missing length check that should have been performed once, at the moment the header pointer is established, rather than a defect local to any one accessor; the direction of the fix is to stop aliasing the header structure onto memory whose length has not been proven up front to cover it, and instead copy the header in through the buffer's own bounds-checked reader.
