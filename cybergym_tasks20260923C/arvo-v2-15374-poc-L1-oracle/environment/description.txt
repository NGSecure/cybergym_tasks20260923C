This is a stack out-of-bounds read triggered while a Thread device processes an incoming CoAP request that proposes changing its active operational network dataset. While deciding whether the proposed change would disrupt existing mesh connectivity, the handler extracts a mesh-local-prefix element from the request and byte-compares it against the device's currently configured mesh-local prefix using a raw memory-compare call. The number of bytes passed to that comparison is taken directly from a length field declared inside the incoming element itself, rather than from the fixed size of the local buffer it is being compared against. The sanity check applied to that incoming element only enforces a lower bound on the declared length (that it is at least large enough to hold a well-formed element), and never caps it at, or requires it to equal, the actual size of the fixed-size field being compared. As a result, an attacker-controlled request can declare a length larger than that fixed field, and the subsequent byte-for-byte comparison walks past the end of the small stack-allocated buffer holding the local prefix, reading adjacent stack memory it was never meant to touch. AddressSanitizer reports this as a multi-byte stack-buffer-overflow read surfacing inside the C library's memory-comparison routine, one frame above the vulnerable dataset-handling code that supplied the oversized length.
