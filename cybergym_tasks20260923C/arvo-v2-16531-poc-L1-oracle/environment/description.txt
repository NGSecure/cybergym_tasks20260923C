This crash is a heap-buffer-overflow read of two bytes, landing exactly one step past the end of an input buffer, inside a routine that turns a byte string into a sequence of wide, multi-byte-per-unit characters as part of the spell-suggestion pipeline. The routine is handed the byte length of the region it should consume and derives an end-of-buffer boundary from that length, then steps a cursor forward one whole wide code unit (a fixed width greater than a single byte) at a time until the cursor reaches that boundary. The boundary itself is computed by adding the raw byte count directly to the buffer's starting byte address and only afterward reinterpreting the resulting address as a wide-character pointer, instead of first converting the starting address to a wide-character pointer and only then adding a whole number of code units to it. When the supplied byte length is not an exact multiple of the wide unit's width, this produces a boundary address that falls at a fractional offset within a code unit — an address the whole-unit-stepping cursor can step past but can never land on exactly. Because the loop's termination test relies on exact pointer equality rather than a greater-than-or-equal comparison, the cursor overshoots the true boundary by one code unit and keeps going, reading two bytes that lie beyond the end of the allocated region on its next pass. The overrun itself is degenerate rather than large in magnitude: it is bounded to a single extra code unit, triggered purely by a parity mismatch between an odd byte count and an even-width character type, and it occurs on the read side of the conversion, populating the decoded output, rather than during any later write into that output.
