libxslt (MSan build): transforming a crafted XML document with a crafted XSLT stylesheet and then serializing the transformation result to a string triggers a use-of-uninitialized-value warning while a text node nested a couple of levels deep inside the result tree's descendant elements is being escaped for output. Root cause: the transformation engine's routine for copying stylesheet text content into the result tree has a fast-path optimization that keeps a single cached pointer to whichever output text buffer it most recently allocated, plus bookkeeping for how many of that buffer's bytes are genuinely populated, so that copying an immediately adjacent run of text can extend the same buffer instead of allocating a brand-new node each time. One of the branches that instead builds its own freshly allocated, independently owned text buffer (taken for text whose source content is shared from an interned string table) omits clearing that cached pointer and its byte-count bookkeeping before returning. When a later, unrelated text copy happens to receive a freshly allocated buffer at the same address as the still-cached one, the fast path wrongly trusts the leftover byte-count bookkeeping as describing this new, different buffer; growing that buffer under the false assumption leaves a trailing span of the reallocated memory never actually written to, and that unwritten span is what gets read once the transformation result is serialized.
