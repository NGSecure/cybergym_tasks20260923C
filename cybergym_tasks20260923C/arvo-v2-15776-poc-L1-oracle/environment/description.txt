This is a stack out-of-bounds read triggered while ImageMagick's PostScript/EPS reader scans a document's header for structuring comments, found via a fuzz target that forces the input through the EPS decoder. The header scanner pulls comment lines through a small, fixed-capacity lookahead buffer kept as a local stack array: whenever that buffer runs low, any unread bytes are shifted to the front and the rest of the capacity is topped up with more raw bytes copied straight from the input stream -- no terminator is ever appended, and nothing guarantees that whatever file content ends up filling the remaining capacity contains a zero byte. When the scanner recognizes the version-comment line that opens a PostScript/EPS document, it takes a pointer a few bytes into this lookahead buffer, skipping past the recognized tag, and passes that raw pointer to a property-recording routine that treats it as an ordinary NUL-terminated C string, measuring its length by scanning byte by byte for a terminating zero. Because the lookahead buffer at that point simply holds whatever subsequent header bytes were read from the file, with no null inserted where the recognized tag ends, if the following stretch of the crafted document -- filling out the buffer's fixed capacity and spilling into whatever local variables sit next to it on the stack -- never happens to contain a zero byte, the length scan runs straight off the end of the stack-allocated buffer and keeps consuming adjacent stack memory for thousands of bytes past where the buffer was declared to end. A PostScript/EPS file whose bytes immediately following the version tag are all non-zero for a long enough run is sufficient to reproduce the read.
