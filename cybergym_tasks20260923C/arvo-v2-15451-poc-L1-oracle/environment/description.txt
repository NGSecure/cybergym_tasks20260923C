A different, related family of crafted X.509 certificates causes the same certificate-extension parsing routine to read past the end of its input buffer while extracting the numeric value of an optional trailing field, again an AddressSanitizer-detected heap-buffer-overflow read.

Root cause: this crash shares its underlying defect with a companion bug in the same routine, but surfaces at a later point in the parsing sequence. The BasicConstraints extension is a SEQUENCE containing a mandatory boolean followed by an OPTIONAL integer. When the parser decides whether that optional integer is present, it works out how many bytes remain by measuring against the end of the extension's whole outer buffer rather than the true end of the SEQUENCE's own encoded content, since it reuses position bookkeeping left over from decoding the mandatory boolean instead of the SEQUENCE's real boundary. That miscalculated remaining-byte count is handed to the shared routine that reads an ASN.1 identifier-and-length header for the optional integer. In this particular crash, the header read itself stays inside the true buffer and appears to succeed, reporting a payload length that looks plausible against the caller's inflated bound, even though that length in fact reaches past the real end of the allocation. The calling routine then walks byte by byte through what it believes is the optional integer's content, accumulating each byte into a numeric value, and this walk runs past the true end of the heap buffer because the length it trusted was never actually validated against the space that really remained.
