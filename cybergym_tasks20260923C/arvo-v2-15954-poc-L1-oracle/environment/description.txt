ImageMagick's PostScript reader (ASan build) scans the file's document-structuring comments through a small fixed-size line-buffering helper that streams the input a chunk at a time and hands back a pointer into its own internal chunk storage for the caller to use as a token (e.g. the PostScript level string following the "%!PS-" marker). That helper's internal read/write bookkeeping can end up inconsistent across refills, so when a header token happens to sit near the tail of a chunk, the pointer returned is not guaranteed to be NUL-terminated within the portion of the chunk that was actually filled from the file. The caller passes this token straight into the image-property machinery as if it were an ordinary C string; the length scan that machinery performs on it then keeps walking past the end of the helper's fixed-size stack storage and into neighboring stack-frame locals that belong to the surrounding parsing routine, producing a stack-buffer-overflow read.
