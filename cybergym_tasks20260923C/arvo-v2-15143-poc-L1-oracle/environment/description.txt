GDAL's OGR fuzz target (ASan build) opens an input through the generic dataset-open dispatcher, which lets the netCDF driver probe the file. While the driver is still deciding whether the file is one it understands, it needs to figure out which revision of the CF (Climate and Forecast) metadata conventions the file declares, so it fetches a small global text attribute through the bundled netCDF library's generic attribute-read call and copies the attribute's raw bytes straight into a fixed-size buffer that the driver keeps as a local on its own stack frame. The number of bytes copied is driven by the attribute's actual stored length rather than being clamped to that buffer's fixed capacity, so a crafted netCDF file whose version-declaring attribute value is longer than the buffer causes the library copy to keep writing once it reaches the end of the local buffer, overrunning into whatever else lives next to it on the stack. This happens purely as a side effect of the driver identifying/opening the file - no other structural content of the netCDF file needs to be valid or exploitable beyond a header the driver recognizes plus an oversized value for the one attribute its version-detection step reads early on. Depending on exactly how long the oversized attribute value is, the same missing bounds check can also surface one step later as an out-of-bounds read, when the driver treats the (no-longer-properly-terminated) local buffer as a plain C string.
