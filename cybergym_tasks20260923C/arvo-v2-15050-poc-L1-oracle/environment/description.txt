A stack-buffer-overflow write is triggered while the SPSS command-language parser decodes a quoted textual value (such as a variable or value label) into a small, fixed-size buffer allocated on the caller's stack. The routine responsible walks the source characters one at a time, treating a backslash as an escape marker (an escaped 't' becomes a literal tab, any other escaped character is copied through as-is) and copying all other characters unchanged into the destination buffer; once the walk completes it appends a terminating NUL byte to mark the end of the decoded string. To keep from writing past the end of that destination buffer, the routine first caps how many source characters it will process whenever the input is at least as long as the buffer's capacity — but that cap is set to the buffer's full capacity rather than one byte less, leaving no headroom for the NUL terminator appended afterward. Because the decode loop advances its output position by at most one byte for every source byte it consumes (it can fall behind on multi-byte escape sequences but never gets ahead), a sufficiently long input containing no escape sequences drives the output position up to the capped limit, i.e. exactly the buffer's full capacity. The terminator is then written one byte beyond the last valid slot in the buffer, overrunning adjacent stack memory. In short: an off-by-one length cap accounts for the decoded data bytes but fails to reserve the extra byte the function unconditionally writes afterward for string termination.
