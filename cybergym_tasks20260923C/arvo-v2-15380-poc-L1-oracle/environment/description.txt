OpenThread's Thread-network stack (radio-receive-done fuzz harness, ASan build) suffers a stack-buffer-overflow read while a router-capable node handles an incoming attach request from a would-be child. The handler parses the one-time challenge value carried in the request into a small, fixed-capacity local object whose value storage holds only a handful of bytes, while that object's separately tracked declared length is copied straight from the untrusted incoming bytes and can claim any value up to the top of a single byte's range, independent of how many bytes the buffer actually has room for or how many were really copied into it. Immediately afterward, while assembling the outgoing reply meant to echo that same challenge value back to the requester, the code that copies the value into the new packet is handed this untrusted declared length rather than a length capped to the object's real, small buffer capacity. Because a crafted attach request can set the declared length far beyond what the buffer holds, the copy walks past the end of the small on-stack value object into whatever else lives further up the stack frame, producing the out-of-bounds read that aborts the process.
